# Hub Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Teammates' phones get the host phone's USB-tethered internet by joining its hotspot and connecting to our app running as a hub.

**Architecture:** The host app opens a protected TCP listener on the hotspot interface, hands each teammate a 10.8.0.N address, and multiplexes their framed IPv4 packets into the existing USB stream; replies are demultiplexed by destination IP. The teammate runs the same APK in client mode with its VpnService pointed at the hub over Wi-Fi. The PC relay is unchanged.

**Tech Stack:** Kotlin (android/), JUnit 4 unit tests run in the Docker build, Python relay (uv/pytest) for the `--serial` option.

**Spec:** `docs/superpowers/specs/2026-11-07-hub-mode-design.md`

## Global Constraints

- Hub port `31417`, pool `10.8.0.10..10.8.0.250`, max `8` clients, hello `b"RTH1"` + 4 bytes, reply 4 bytes, keepalive every `10` s.
- Host address stays `10.8.0.2`; DNS `10.8.0.1`; MTU `1400`; frames at most `1500` bytes.
- Hub and client sockets are always protected; client socket is bound to the Wi-Fi `Network`.
- Commits authored as Utsab Kundu <utsabkundu.laserpowerinfra@gmail.com>, no attribution lines.

## Review Focus

1. A client that sends a packet with a forged source (another client's address) must be dropped by the hub, never forwarded (`HubTest.forged source is rejected` via `AddressPool`/`ipv4Source` contract; `HubServer` reader checks it).
2. A client that disconnects must release its address so the next connect gets it back (`HubTest.release makes address reusable`).
3. A hello asking for an address already held by another live client must get a different one (`HubTest.wanted address in use yields another`).
4. A reply packet from the relay for an unknown 10.8.0.N must be dropped, not written to the host tunnel (`Tunnel` demux: own address or hub, else drop; verified in Task 8 step with relay `--verbose`).
5. With two phones plugged in, `rtether run --serial` must pick the named one (`test_cli.py::test_serial_selects_device`).
